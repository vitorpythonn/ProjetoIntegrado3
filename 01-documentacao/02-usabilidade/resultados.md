# Resultados do Teste de Usabilidade

## 1. Introdução

Os testes foram realizados no GitHub utilizando o repositório `ProjetoIntegrado3`. A avaliação considerou a navegação pela plataforma, a organização das informações e a localização das principais funcionalidades utilizadas durante o projeto.

Foram executados cinco testes práticos, acompanhados de evidências visuais.

## 2. Resultados dos testes

### Teste 01 — Localização e acesso ao repositório

Foi avaliada a localização e abertura do repositório `ProjetoIntegrado3`.

**Resultado:** o repositório foi localizado e acessado, permitindo visualizar sua estrutura e as informações disponibilizadas na página inicial.

**Evidência:** `01-repositorio.png`

### Teste 02 — Localização e navegação pelos arquivos

Foi avaliada a navegação pela estrutura de diretórios e arquivos do projeto.

**Resultado:** foi possível acessar os diretórios e retornar à estrutura principal do repositório por meio da interface disponibilizada pelo GitHub.

**Evidência:** `02-arquivos.png`

### Teste 03 — Localização de Issues

Foi avaliada a localização da funcionalidade `Issues`.

**Resultado:** a funcionalidade foi localizada na interface do repositório e sua área pôde ser acessada.

**Evidência:** `03-issues.png`

### Teste 04 — Localização de Pull Requests

Foi avaliada a localização da funcionalidade `Pull requests`.

**Resultado:** a funcionalidade foi localizada na interface do repositório e sua área pôde ser acessada.

**Evidência:** `04-pull-requests.png`

### Teste 05 — Localização das configurações

Foi avaliada a localização da área `Settings`.

**Resultado:** a área de configurações foi localizada e acessada sem realização de alterações.

**Evidência:** `05-settings.png`

## 3. Aspectos positivos

Durante os testes, foram identificados os seguintes aspectos positivos:

* organização dos arquivos em diretórios;
* acesso centralizado às principais funcionalidades do repositório;
* identificação das áreas de Issues e Pull Requests;
* disponibilização de configurações específicas do repositório;
* apresentação estruturada das informações do projeto;
* possibilidade de navegar entre diretórios e retornar à estrutura anterior.

## 4. Aspectos negativos

Foram identificados alguns pontos que podem dificultar a utilização, principalmente para usuários que ainda não possuem familiaridade com plataformas de controle de versão:

* grande quantidade de funcionalidades disponíveis na interface;
* utilização de termos técnicos como `Issues`, `Pull requests` e `Settings`;
* algumas funcionalidades podem não ser imediatamente compreendidas por usuários iniciantes;
* a quantidade de opções disponíveis pode aumentar a complexidade da interface.

## 5. Acessibilidade

A avaliação considerou aspectos perceptíveis durante a utilização da interface, como organização visual, identificação dos elementos e clareza das opções apresentadas.

Não foram realizados testes especializados com leitores de tela, ferramentas automatizadas ou dispositivos de tecnologia assistiva. Portanto, não é possível afirmar a conformidade completa da plataforma com critérios técnicos de acessibilidade.

## 6. Considerações finais

Os testes demonstraram que o GitHub disponibiliza uma estrutura organizada para gerenciamento de repositórios e acesso às principais funcionalidades avaliadas.

As principais dificuldades estão relacionadas à quantidade de recursos disponíveis e ao uso de terminologia específica de desenvolvimento de software, fatores que podem representar maior dificuldade para usuários iniciantes.
